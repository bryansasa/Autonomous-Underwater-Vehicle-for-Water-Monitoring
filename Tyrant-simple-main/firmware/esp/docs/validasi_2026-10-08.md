Tujuh kelompok uji native: **PASS**, menggunakan kode produksi dan GPIO/I2C palsu:

1. Timeout heartbeat tanpa menunggu diagnostik, reconnect, rollover millis.
2. Empat channel power, ON ditolak saat host hilang, OFF tetap diterima.
3. Parsing EZO, NACK, payload kosong/rusak, NaN, data stale, umur kanal dan uptime 64-bit.

## Perbaikan setelah uji ESP fisik

Pengguna melaporkan graph/heartbeat ESP berhasil, tetapi diagnostik mencatat
connection_count=29, disconnect_count=28, ping_failures=426 dan publish_failures=15.
Counter sempat bertambah lagi. Jumlah ini adalah akumulasi sejak boot; belum
menetapkan penyebab fisik USB/agent. Review menemukan kebijakan lama: ping/publish
timeout 20 ms dan satu kegagalan langsung membongkar sesi.

Firmware kini memakai timeout 100 ms, tiga ping gagal beruntun, serta toleransi
publish sementara sampai 3 detik tanpa publish sukses. Tambahan uji native
menverifikasi toleransi error sesaat, pemulihan setelah kegagalan berkelanjutan,
reset rentetan kegagalan dan rollover millis. Delapan kelompok uji PASS;
build target PASS (5,13 detik; RAM 42.644 byte, flash 372.357 byte).
Pengguna telah melaporkan upload pembaruan dan pengujian berhasil. Cuplikan 30 detik:
connection_count tetap 1, disconnect_count tetap 0; ping_failures naik 11→12 dan
publish_failures naik 1→2. Koneksi bertahan meskipun error sesaat masih tercatat.
Pengguna juga melaporkan ACK daya, timeout heartbeat, dan penghentian/pemulihan
agent sesuai status. Hasil tersebut adalah laporan operator, bukan uji otomatis asisten.

Interface host dibangun di esp/host_ws: keenam message termasuk SensorPowerStatus
beserta C type support dapat dimuat. Pengguna juga berhasil menampilkan schema
SensorPowerStatus setelah source overlay dan kemudian melaporkan uji berhasil.

## Profil simulasi tanpa sensor

Profil `esp32-s3-sim` menggunakan backend data buatan dan namespace
`/tyrant/payload_sim`. Tidak ada akses GPIO MOSFET, ADC atau transaksi I2C.
Lima kelompok uji native simulasi PASS, dengan AddressSanitizer/UndefinedBehaviorSanitizer:
isolasi namespace/IO dan warm-up, gradien/DO kritis, baterai rendah, kegagalan
EC/INA dan pemulihan, serta aturan heartbeat/perintah daya. Delapan kelompok uji
hardware tetap PASS setelah penambahan profil ini.

Panduan upload, skenario 180 detik dan rekaman rosbag ada di
[uji_simulasi_payload.md](uji_simulasi_payload.md). Simulasi belum di-upload atau
diuji melalui USB oleh asisten; belum menghubungkan data ke kedalaman atau titik misi.
Log dan fingerprint simulasi dipisahkan dari hasil profil hardware.

Build `esp32-s3-sim` PASS (249,67 detik termasuk unduhan dan persiapan micro-ROS).
Hasil lengkap: [log build simulasi](../simulation-build-validation.log),
[log uji native simulasi](../simulation-native-validation.log),
[fingerprint simulasi](../simulation-validation-result.json).
